## 增值服务准入

- 分类：远程工作区、AI CLI、Git/tmux 可视化、移动端工作流效率和上下文工具箱。
- 非目标：不研究、不重写 Termux 原始终端、PTY、包管理、本地 shell、基础会话、基础快捷键或基础文件
  能力。原始 Termux 能力只做兼容守护和“不受影响”回归保护。
- 风险控制：稳定版不加入候选版之外的新功能；AI 历史入口不自动恢复最近会话；AI 启动不自动进入 tmux；
  Git 检查走结构化工作台；SSH 粘贴解析只提取目标参数。

## 稳定版门禁

1. `termuxpro-version.properties` 必须为 `0.9.6` / `90602`，且发布说明文件存在。
2. `versionCode=90602` 必须高于 `0.9.6-rc.1` 的 `90601`。
3. `git diff --check`、`./scripts/validate-skills.sh`、`./test/version-metadata-test.sh`、
   `./test/workflow-trigger-policy-test.sh`、`./test/release-apk-device-smoke-test.sh` 和
   `./test/release-abi-gate-test.sh` 必须通过。
4. 稳定准备分支合入 `dev` 前，分支 CI 与适用门禁必须通过，并等待合入 `dev` 后收尾 CI。
5. `dev → master` 发布 PR 的 CI 必须通过。
6. `v0.9.6` 稳定标签必须指向 `master` 合并提交，Release workflow 必须完成签名 APK 构建、覆盖升级、
   运行时冒烟和 GitHub Release 创建。
7. 稳定 Release 必须是非草稿、非预发布，附件包含 APK、`SHA256SUMS` 和 `APK_SIGNATURE.txt`。
8. 稳定 Release 完成后必须将 `dev` 对齐 `master` 并等待收尾 CI。
