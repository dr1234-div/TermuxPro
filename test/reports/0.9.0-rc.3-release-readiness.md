# TermuxPro 0.9.0-rc.3 候选发布评审记录

## 当前结论

候选状态：`READY TO PUBLISH`。`0.9.0-rc.2` 的 APK 构建和覆盖安装已到达设备验收阶段，但 Release
workflow `33501845633` 在设备命令空输出路径触发脚本自身错误，公开 GitHub Release 未创建。PR #143
已修复该验收脚本问题并通过 PR CI 与 dev 收尾 CI，因此递增发布 `0.9.0-rc.3`，不覆盖 `v0.9.0-rc.2`
标签。

## 冻结范围

- `0.9.0-rc.1` 已冻结的终端工具箱增值入口范围。
- PR #140：候选 Release 等待增加 Release 页面与附件兜底，减少已发布后仍等待到超时的失败噪声。
- PR #141：AI CLI 启动弹窗补充 Claude 共享账号风险和 Codex 当前项目确认说明。
- PR #143：Release 设备验收脚本允许空设备输出进入明确诊断路径，并补充回归测试。

## 非目标

- 不增加新的 Git/tmux/工作区功能。
- 不解析 Claude/Codex 历史数据。
- 不研究或重做 Termux 原始终端、PTY、包管理、本地 shell、基础会话或基础快捷键能力。

## 候选门禁

1. `termuxpro-version.properties` 必须为 `0.9.0-rc.3` / `90003`，发布说明文件存在。
2. `versionCode=90003` 必须高于 `0.9.0-rc.2` 的 `90002`，且后续稳定版必须继续递增。
3. `git diff --check` 必须通过。
4. `./scripts/validate-skills.sh` 必须通过。
5. `./test/version-metadata-test.sh`、`./test/pre-push-smoke-test.sh` 和
   `./test/workflow-trigger-policy-test.sh` 必须通过。
6. `./test/release-apk-device-smoke-test.sh` 必须覆盖空设备输出诊断路径，且日志不能出现
   `parameter null or not set`。
7. `./test/release-abi-gate-test.sh` 必须通过。
8. 候选分支 `dev_release090Rc3_20260901 → dev` 的 CI 必须通过，并等待合入 `dev` 后收尾 CI。
9. 候选标签 `v0.9.0-rc.3` 必须由自动 PR 流水线在合并提交上创建，不覆盖既有标签。
10. Release workflow 必须完成签名 APK 构建、覆盖升级、运行时冒烟和 GitHub Pre-release 创建。

## 产品边界裁定

- 本候选版只处理 TermuxPro 发布链路稳定性和已冻结的远程 AI 开发体验，不把 Termux 原始能力作为
  新功能研究对象。
- Termux 原始终端、PTY、包管理、本地 shell、基础会话和基础快捷键能力只作为“不受影响”回归面。
