# TermuxPro 0.6.0-rc.2 发布评审记录

## 当前结论

候选版状态：`READY_FOR_RC_PR`。`v0.6.0-rc.1` 标签已创建但 Release workflow 在覆盖升级验收阶段失败，未
创建公开 GitHub Release。失败根因是发布门禁尝试把公开 `arm64-v8a` APK 安装到 GitHub x86_64 模拟器。
本轮不覆盖 `v0.6.0-rc.1` 标签，递增到 `0.6.0-rc.2` 重新发布。

## 冻结范围

- PR #69：支持从远端跟踪分支创建本地跟踪分支并切换。
- PR #70：统一 Git 工作台弹窗可读性。
- PR #72：提升多工作区入口可发现性，单工作区时不展示伪选择器。
- PR #73：支持新建本地分支并切换。
- PR #74：Git 概览拆分已暂存/未暂存状态，并支持暂存全部/取消暂存全部。
- PR #76：修复 Release 模拟器验收 ABI 不匹配；公开 APK 保持 arm64，模拟器门禁使用同签名 x86_64 APK。

## 本地证据

- `0.6.0-rc.1` 失败证据：Release run `33412664689` 在“验收待发布签名 APK 的覆盖升级”步骤失败；候选
  APK 元数据为 `native-code: 'arm64-v8a'`，而 Release workflow 使用 x86_64 模拟器。
- PR #76 本地 `TERMUXPRO_USE_CHINA_MIRROR=1 ./scripts/test-all.sh && git diff --check` 已通过，覆盖
  `release-abi-gate-test.sh`、`release-apk-device-smoke-test.sh` 和 workflow 策略测试。
- PR #76 GitHub CI、Emulator UI 和 dev merge commit 收尾 CI 均已通过。
- GitHub check suite 诊断仍显示仓库自身 Actions 无风险；`vercel`、`4everland`、`cursor` 的 queued 0 job
  外部空检查未被设为必需检查，属于页面噪声。

## 发布门禁

1. `termuxpro-version.properties` 必须为 `versionName=0.6.0-rc.2`、`versionCode=60002`，高于 `0.6.0-rc.1`。
2. 本地 `TERMUXPRO_USE_CHINA_MIRROR=1 ./scripts/test-all.sh && git diff --check` 必须通过。
3. release PR head 的完整 CI 与 Emulator UI 必须通过。
4. release PR 合入 dev 后，merge commit 收尾 CI 必须通过。
5. 标签 `v0.6.0-rc.2` 必须指向 release PR 合入后的 dev merge commit。
6. Release 工作流必须先校验公开 arm64 APK，再用 x86_64 门禁 APK 完成覆盖升级与启动冒烟，最后创建
   GitHub Pre-release。
7. Release 必须非 Draft、标记为 Pre-release，并包含 APK、`SHA256SUMS` 和 `APK_SIGNATURE.txt`。

## 发布结论

待自动发布流水线完成后补充标签、Release run、APK SHA-256、签名报告和覆盖升级证据。任一门禁失败则
停止候选发布，修复后继续递增候选编号，不覆盖既有标签。
