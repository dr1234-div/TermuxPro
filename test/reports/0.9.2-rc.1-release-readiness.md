# TermuxPro 0.9.2-rc.1 候选发布评审记录

## 当前结论

候选版状态：`RELEASED`。`dev` 自 `0.9.1` 稳定版后已合入多项用户可见的 TermuxPro 增值服务改进，并且
对应研发分支 CI、模拟器 UI、候选发布分支、合入 `dev` 后收尾 CI、Release workflow、正式签名 APK
构建和覆盖升级验收均已通过。`v0.9.2-rc.1` GitHub Pre-release 已创建。

- 候选版本：`0.9.2-rc.1`
- 候选 `versionCode`：`90201`

## 冻结范围

- PR #160：终端内 AI 工具箱启动入口，减少远程开发时返回首页的跳转成本。
- PR #161：Claude Code/Codex CLI 启动前展示远端目标，降低误进入错误服务器或目录的风险。
- PR #162：tmux 会话中心优先展示当前工作区会话。
- PR #163：强化增值服务准入边界，明确 Termux 原始功能只作为兼容回归面。
- PR #164：tmux 会话中心补充操作边界提示，非当前工作区会话默认只允许显式进入。
- PR #165：Git 工作台支持按文件查看改动、暂存单文件和取消暂存单文件。

## 增值服务准入裁定

- AI 工具箱启动入口：分类为 `AI CLI` 与 `上下文工具箱`，可进入主线候选范围。
- AI CLI 目标提示：分类为 `AI CLI` 与 `远程工作区`，可进入主线候选范围。
- tmux 会话优先级与安全提示：分类为 `tmux/Git 可视化` 与 `远程工作区`，可进入主线候选范围。
- Git 文件级暂存管理：分类为 `tmux/Git 可视化` 与 `移动端工作流效率`，可进入主线候选范围。
- Termux 原始终端、PTY、包管理、本地 shell、基础会话和基础快捷键：不作为本轮新增能力，只作为回归保护。

## 候选发布门禁

1. `termuxpro-version.properties` 必须为 `0.9.2-rc.1` / `90201`，且发布说明文件存在。
2. `versionCode=90201` 必须高于 `0.9.1` 稳定版 `90102`。
3. `git diff --check`、`./test/pre-push-smoke-test.sh` 和 `./scripts/pre-push-smoke.sh origin/dev` 必须通过。
4. 候选发布分支合入 `dev` 前，分支 CI、适用模拟器 UI 和自动 PR 工作流必须通过。
5. 候选合入 `dev` 后，收尾 CI 必须通过。
6. `v0.9.2-rc.1` 标签必须由候选发布自动化从唯一版本源创建，Release workflow 必须完成签名 APK 构建、
   覆盖升级、运行时冒烟和 GitHub Pre-release 创建。
7. 候选 Release 必须包含 APK、`SHA256SUMS` 和 `APK_SIGNATURE.txt`，并记录 APK SHA-256。

## P0/P1 裁定

- 当前冻结范围没有已知启动崩溃、安装失败、无法 SSH、误杀真实 tmux、数据损坏或 Release 产物不可安装
  证据。
- Git 文件级操作只修改暂存区，不执行提交、推送、reset 或工作区丢弃，风险边界可控。
- 原始 Termux 能力不是本轮主线研发对象；后续测试只验证 TermuxPro 增值层没有影响原始能力。
