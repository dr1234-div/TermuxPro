# TermuxPro 0.9.0-rc.2 候选发布评审记录

## 当前结论

候选状态：`READY TO PUBLISH`。`0.9.0-rc.1` 已成功发布，但 `dev` 随后合入了一个发布自动化修复和一个
用户可见的 AI CLI 上下文提示。按发布纪律，`0.9.0` 正式版不能直接包含未经候选验证的用户可见改动，
因此冻结 `0.9.0-rc.2`。

## 冻结范围

- `0.9.0-rc.1` 已冻结的终端工具箱增值入口范围。
- PR #140：候选 Release 等待增加 Release 页面与附件兜底，减少已发布后仍等待到超时的失败噪声。
- PR #141：AI CLI 启动弹窗补充 Claude 共享账号风险和 Codex 当前项目确认说明。

## 非目标

- 不增加新的 Git/tmux/工作区功能。
- 不解析 Claude/Codex 历史数据。
- 不研究或重做 Termux 原始终端、PTY、包管理、本地 shell 或基础快捷键能力。

## 候选门禁

1. `termuxpro-version.properties` 必须为 `0.9.0-rc.2` / `90002`，发布说明文件存在。
2. `versionCode=90002` 必须高于 `0.9.0-rc.1` 的 `90001`，且后续稳定版必须继续递增。
3. `./scripts/validate-skills.sh` 必须通过。
4. `git diff --check` 必须通过。
5. `./test/version-metadata-test.sh`、`./test/pre-push-smoke-test.sh` 和
   `./test/workflow-trigger-policy-test.sh` 必须通过。
6. `./test/dialog-readable-style-test.sh` 必须通过。
7. `AiCliLaunchCommandTest` 必须证明新建/历史命令策略未变，且 Claude/Codex 使用不同提示。
8. 候选分支 `dev_release090Rc2_20260901 → dev` 的 CI 必须通过，并等待合入 `dev` 后收尾 CI。
9. 候选标签 `v0.9.0-rc.2` 必须由自动 PR 流水线在合并提交上创建，不覆盖既有标签。
10. Release workflow 必须完成签名 APK 构建、覆盖升级、运行时冒烟和 GitHub Pre-release 创建。

## P0/P1 裁定

- AI CLI 上下文提示属于共享 Claude 账号和移动端恢复路径的 P1 体验修订，允许递增候选编号。
- 发布自动化等待兜底属于交付噪声治理，不改变 APK 业务逻辑，但必须进入候选流程验证。
- 本轮不触碰 Termux 原始终端能力；原始能力只作为“不受影响”回归面。
