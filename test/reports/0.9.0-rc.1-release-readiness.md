# TermuxPro 0.9.0-rc.1 候选发布评审记录

## 当前结论

候选状态：`PUBLISHED`。`dev` 自 `0.8.1` 稳定版后已有多项用户可见的远程开发增值入口，且最新研发 PR、
模拟器 UI、`dev` 合并后 CI、Release 签名 APK 构建和模拟器覆盖升级验收均已通过。已冻结并发布
`0.9.0-rc.1`，不继续把已完成入口优化无限堆在 `dev`。

## 候选门禁

1. `termuxpro-version.properties` 必须为 `0.9.0-rc.1` / `90001`，发布说明文件存在。
2. `versionCode=90001` 必须高于 `0.8.1` 稳定版 `80102`。
3. `./scripts/validate-skills.sh` 必须通过。
4. `git diff --check` 必须通过。
5. `./test/version-metadata-test.sh`、`./test/pre-push-smoke-test.sh` 和
   `./test/workflow-trigger-policy-test.sh` 必须通过。
6. `./test/github-cli-wrapper-test.sh`、`./test/github-check-suites-test.sh` 和
   `./test/dialog-readable-style-test.sh` 必须通过。
7. 候选分支 `dev_release090Rc1_20260901 → dev` 的 CI 与 Emulator UI 必须通过，并等待合入 `dev`
   后收尾 CI。
8. 候选标签 `v0.9.0-rc.1` 必须由自动 PR 流水线在合并提交上创建，不覆盖既有标签。
9. Release workflow 必须完成签名 APK 构建、覆盖升级、运行时冒烟和 GitHub Pre-release 创建。

## P0/P1 裁定

- 本轮触达终端内远程开发高频路径，但不改动 Termux PTY、原始滚动输入策略、包管理、通知、锁屏保活或
  Android 存储边界；不触发实体真机硬门禁。
- 所有新入口均复用活动工作区快照，工作区无效时失败关闭，不向当前 shell 注入命令。
- Web 预览只绑定手机 loopback，不暴露局域网端口。
- CI 自动化变更不隐藏真实失败；预合并和 dev 收尾 CI 仍必须成功。
