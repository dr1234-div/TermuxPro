# TermuxPro 0.3.0-rc.1 发布评审记录

## 当前结论

候选版状态：`PUBLISHED / PASS`。标签 `v0.3.0-rc.1`、正式签名 APK、SHA-256 与签名报告已经由 Release
流水线发布；`0.2.0 → 0.3.0-rc.1` 已在隔离 Android 模拟器完成覆盖升级、Launcher 启动、UID 保持、
进程存活、桌面名称及致命崩溃检查。

稳定版状态：`HOLD`。候选通过不等于 `0.3.0` 稳定版 READY；API 21/28、真实 SSH/tmux/AI CLI 主旅程和
候选范围 P0/P1 裁定仍未形成完整证据，不得直接将当前 `dev` 合入 `master` 后打稳定标签。

## 冻结范围

- PR #34：连接可信状态与就地复检。
- PR #35：终端前台反馈可读性。
- PR #36：终端会话与工作台入口可发现性。
- PR #37：远程 Git 工作台基础闭环。
- PR #38：按工作区隔离的自定义快捷指令 CRUD 与安全执行。

冻结后不再并入新的 P2 或普通功能；门禁失败只允许修复候选范围内的缺陷并递增候选编号。

- 上述 PR 合入前均通过全模块测试和 GitHub 模拟器默认/200% 字体门禁。
- Git 使用真实临时仓库覆盖普通分支、detached HEAD、脏工作树、无上游、切换冲突和非仓库错误。
- 快捷指令覆盖 CRUD、排序/启停、持久化、工作区隔离、秘密拒绝、危险确认与失效目标失败关闭。
- UI/UX 曾因弹窗黑字和超大字体标题断行驳回，修复后的模拟器截图已通过复核。
- Release run `33315376835` 已验证 Release/R8、ARM64 ABI、版本、Launcher、v1/v2 签名和公开证书。
- Emulator UI run `33316282074` 已验证正式签名 APK 从 0.2.0 覆盖升级到 0.3.0-rc.1；当前 `dev` 的
  CI run `33352497238` 通过，候选后只新增发布门禁和研发治理，不包含新的应用功能。

## 候选版已完成条件

以下条件已经完成，保留为候选版证据索引：

1. 发布分支 PR 的 `test` 与候选范围 `emulator-ui` 全绿，并复核默认/200% 字体截图。
2. `build-termuxpro-release.sh` 验证 `0.3.0-rc.1`、`versionCode=30001`、ARM64 ABI、v1/v2 签名及公开证书指纹。
3. 候选 APK、SHA-256、签名报告和构建信息来自同一提交，发布说明与实际行为一致。
4. 不存在候选范围内未关闭 P0/P1 回归；真实 SSH、tmux、Claude Code 和 Codex CLI 的未覆盖项明确列为限制。
5. 标签 `v0.3.0-rc.1` 位于发布 PR 合入后的 `dev` 提交，流水线已创建非 Draft 的 Pre-release。

## 稳定版边界

候选发布不等于 `0.3.0` 稳定版 READY。稳定版必须基于候选 APK 完成适用的 Android 运行时矩阵，关闭
候选范围内的 P0/P1，并使用高于 `30001` 的 `versionCode` 经 `dev → master` 发布 PR 和标签流水线发布。
