# TermuxPro 0.9.3 稳定发布评审记录

稳定版状态：`READY`。`0.9.3` 是 `0.9.2` 稳定标签发布失败后的发布门禁修复版，应用用户功能沿用
`0.9.2-rc.1` 已验证范围，不加入新的未验证功能。当前等待 hotfix 分支、`dev → master` 发布 PR、
master CI、稳定标签、Release workflow 和公开稳定 GitHub Release 完成。

## 冻结范围

- 用户功能范围沿用 `0.9.2-rc.1`：AI CLI 终端入口/目标提示、tmux 当前工作区优先展示与操作边界提示、
  Git 单文件暂存管理。
- 发布门禁修复：`scripts/verify-release-apk-on-device.sh` 显式启动 Launcher Activity，等待进程稳定态，
  并保留完整失败证据。

## 稳定版门禁

1. `termuxpro-version.properties` 必须为 `0.9.3` / `90302`，且发布说明文件存在。
2. `versionCode=90302` 必须高于 `0.9.2` 的 `90202` 与 `0.9.2-rc.1` 的 `90201`。
3. `git diff --check`、`./scripts/validate-skills.sh`、`./test/version-metadata-test.sh`、
   `./test/workflow-trigger-policy-test.sh`、`./test/release-apk-device-smoke-test.sh` 和
   `./test/release-abi-gate-test.sh` 必须通过。
4. hotfix 分支 PR 合入 `dev` 前，分支 CI 与适用门禁必须通过，并等待合入 `dev` 后收尾 CI。
5. `dev → master` 发布 PR 的 CI 必须通过。
6. `v0.9.3` 稳定标签必须指向 `master` 合并提交，Release workflow 必须完成签名 APK 构建、覆盖升级、
   运行时冒烟和 GitHub Release 创建。
7. 稳定 Release 必须是非草稿、非预发布，附件包含 APK、`SHA256SUMS` 和 `APK_SIGNATURE.txt`。
8. 稳定 Release 完成后必须将 `dev` 对齐 `master` 并等待收尾 CI。

## P0/P1 裁定

- 当前没有应用启动崩溃、安装失败、无法 SSH、误杀 tmux、数据损坏或 Release 产物不可安装证据。
- `0.9.2` 失败属于发布验收脚本假阴性；修复后必须用同一 Release workflow 重新证明。
- 原始 Termux 能力不是本轮主线研发对象；只作为增值层不破坏的兼容回归面。
