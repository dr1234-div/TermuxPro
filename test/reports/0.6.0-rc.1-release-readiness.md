# TermuxPro 0.6.0-rc.1 发布评审记录

## 当前结论

候选版状态：`READY_FOR_RC_PR`。`dev` 自 `v0.5.1` 后已有多项用户可见改动，主要集中在 Git 工作台提交前
操作和多工作区入口可发现性，符合冻结候选版条件。冻结范围不并入下一轮 P2 或未验证功能。

## 冻结范围

- PR #69：支持从远端跟踪分支创建本地跟踪分支并切换。
- PR #70：统一 Git 工作台弹窗可读性。
- PR #72：提升多工作区入口可发现性，单工作区时不展示伪选择器。
- PR #73：支持新建本地分支并切换。
- PR #74：Git 概览拆分已暂存/未暂存状态，并支持暂存全部/取消暂存全部。

## 本地证据

- 当前候选冻结前，PR #69、#70、#72、#73、#74 均已通过本地验证、GitHub CI、Emulator UI 和 dev merge
  commit 收尾 CI。
- `scripts/check-github-check-suites.sh --sha 1e358ea1c5ce24e2419194c6a00a8a953060cd30` 与
  `--sha dbe9aaae380502f588a5e9d5bfbbb53b31878671` 均显示 `githubActionsRisk=[]`；`vercel`、
  `4everland`、`cursor` 仍会挂载 queued 且 0 job 的外部空 check suite，但 `master`、`dev` 均未把
  它们设为必需检查，因此属于 PR 页面噪声，不阻断研发合并或候选发布。
- 候选冻结提交必须通过本地
  `TERMUXPRO_USE_CHINA_MIRROR=1 ./scripts/test-all.sh && git diff --check`，包含版本元数据、稳定基线选择、
  GitHub CLI 封装、workflow 触发策略、终端触摸 scrollback 策略、Release APK 冒烟脚本、Skill 校验和
  Gradle 全量单元测试。

## 发布门禁

1. `termuxpro-version.properties` 必须为 `versionName=0.6.0-rc.1`、`versionCode=60001`，高于 `0.5.1`。
2. 本地 `TERMUXPRO_USE_CHINA_MIRROR=1 ./scripts/test-all.sh && git diff --check` 必须通过。
3. release PR head 的完整 CI 与 Emulator UI 必须通过。
4. release PR 合入 dev 后，merge commit 收尾 CI 必须通过。
5. 标签 `v0.6.0-rc.1` 必须指向 release PR 合入后的 dev merge commit。
6. Release 工作流必须先完成待发布签名 APK 覆盖升级验收，再创建 GitHub Pre-release。
7. Release 必须非 Draft、标记为 Pre-release，并包含 APK、`SHA256SUMS` 和 `APK_SIGNATURE.txt`。

## 发布结论

待自动发布流水线完成后补充标签、Release run、APK SHA-256、签名报告和覆盖升级证据。任一门禁失败则
停止候选发布，修复后递增候选编号，不覆盖既有标签。
