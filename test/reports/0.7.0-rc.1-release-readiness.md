# TermuxPro 0.7.0-rc.1 发布评审记录

## 当前结论

候选版状态：`READY_FOR_RC_PR`。`dev` 自 `v0.6.0` 稳定版后已有用户可见 Git 工作台改动，符合冻结候选版
条件。本轮冻结范围只包含已合入 `dev` 且完成分支 CI、Emulator UI 与 dev 收尾 CI 的改动；候选发布门禁
失败时只修复当前范围，不并入新的普通功能。

## 冻结范围

- PR #84：记录 `0.6.0` 正式版发布证据，不改变应用运行时行为。
- PR #85：修复稳定版本证据补录分支误触发候选发布的 CI 规则。
- PR #86：Git 工作台支持提交已暂存修改。
- PR #87：Git 工作台支持刷新当前 upstream 所属远端。
- PR #88：Git 工作台支持安全快进拉取。
- PR #89：Git 工作台支持安全推送当前分支到 upstream。

## 候选版前置证据

- 最新稳定版：`v0.6.0`，GitHub Release 非 Draft、非 Pre-release。
- `origin/dev` 领先 `origin/master` 12 个提交，其中用户可见功能集中在 PR #86-#89。
- PR #86、#87、#88、#89 均已通过分支 CI、Emulator UI、auto PR 合并和合并后 `dev` 收尾 CI。
- 当前候选元数据：`versionName=0.7.0-rc.1`、`versionCode=70001`、
  `releaseNotes=docs/RELEASE_NOTES_0.7.0-rc.1.md`。
- `versionCode=70001` 高于 `0.6.0` 的 `60004`。

## 发布门禁

1. 候选元数据 PR 的完整 CI 与 Emulator UI 必须通过。
2. 候选元数据 PR 合入 `dev` 后，merge commit 收尾 CI 必须通过。
3. 标签 `v0.7.0-rc.1` 必须指向候选 PR 合入后的 `dev` merge commit。
4. Release 工作流必须先构建正式签名 APK，再使用稳定版基线执行覆盖升级与启动冒烟。
5. Release 必须非 Draft、标记为 Pre-release，并包含 APK、`SHA256SUMS` 和 `APK_SIGNATURE.txt`。
6. 运行时证据必须非空，并记录设备型号、Android 版本、ABI、输入法、进程和无 AndroidRuntime 崩溃结论。

## P0/P1 裁定

- 本轮候选范围内没有引入 SSH、tmux ownership、Claude 共享账号历史或终端 PTY 新风险。
- Git 写操作均采用失败关闭策略：不 force push、不自动 merge/rebase、不丢弃工作树、不覆盖远端分支。
- `0.5.0` 触摸滑动无法滚动历史输出的问题已在 `0.5.1+` 修复，并由 `test/terminal-touch-scrollback-test.sh`
  纳入回归；如果 `0.7.0-rc.1` 复现，应重新升为 P0。

`0.7.0` 稳定发布；不得跳过候选体验直接更新 `master`。
