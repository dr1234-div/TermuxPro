# TermuxPro 0.6.0 正式版发布评审记录

## 当前结论

正式版状态：`READY_FOR_RELEASE_PR`。`0.6.0-rc.3` 候选版已完成公开发布、签名 APK 覆盖升级验收、
完整 CI、模拟器 UI 和 merge commit 收尾 CI；PR #81 已补强发布设备门禁的运行时证据，消除了
`android-runtime.txt` 空文件静默通过的问题。当前冻结范围没有未关闭 P0/P1 阻断，允许推进
`dev → master` 和 `v0.6.0` 稳定发布。

## P0/P1 裁定

- 当前全局 Backlog 中仍保留 SSH、tmux、Claude Code 共享账号隔离、AI 会话中心和真机验收等长期质量项；
  这些属于持续产品主线，不在本次 0.6.0 冻结范围内直接新增风险。
- 本次冻结范围内的用户可见变更集中在 Git 工作台、工作区入口和发布门禁。对应功能已经通过本地测试、
  GitHub CI、模拟器默认/200% 字体截图和候选发布门禁；未发现阻断稳定版的 P0/P1。
- 若稳定发布流程或正式 APK 体验发现启动、覆盖升级、SSH 主路径、触摸滚动、Git index 安全或深色文字
  不可读回归，立即停止稳定发布并重新进入候选修复流程。

## 稳定版发布门禁

1. 本地 `TERMUXPRO_USE_CHINA_MIRROR=1 ./scripts/test-all.sh && git diff --check` 必须通过。
2. 稳定版元数据 PR 的完整 CI 与 Emulator UI 必须通过。
3. 稳定版元数据 PR 合入 `dev` 后，merge commit 收尾 CI 必须通过。
4. 创建 `dev → master` 发布 PR；发布 PR 的完整 CI 与 Emulator UI 必须通过。
5. 发布 PR 合入 `master` 后，在 `master` 合并提交创建不可覆盖标签 `v0.6.0`。
6. Release 工作流必须先完成正式签名 APK 覆盖升级验收，再创建 GitHub Stable Release。
7. Release 必须非 Draft、非 Pre-release，并包含 APK、`SHA256SUMS` 和 `APK_SIGNATURE.txt`。
8. 稳定 Release 的 `android-runtime.txt` 证据必须非空，并记录设备/系统/ABI/输入法/进程/无崩溃结论。
9. 稳定 Release 完成后，`dev` 必须对齐 `master` 发布提交并等待收尾 CI 成功。

## 发布结论

进入 `dev → master` 稳定发布流程。若任一门禁失败，停止发布并记录失败证据；不得覆盖既有
`v0.6.0-rc.1`、`v0.6.0-rc.2`、`v0.6.0-rc.3` 或未来稳定标签。
