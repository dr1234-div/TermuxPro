# TermuxPro 0.5.1 正式版发布评审记录

## 当前结论

正式版状态：`READY_FOR_RELEASE_PR`。`v0.5.0` GitHub Release 在公开创建前收到用户反馈：手机终端页面
上下滑动被转换为命令行上下键，无法自然查看历史输出。该问题影响 Codex CLI / Claude Code 的核心阅读
体验，判定为 P1 发布阻断。已取消 `v0.5.0` Release run `33394175165`，未创建公开 GitHub Release；
稳定标签不删除、不移动，改用 `0.5.1` 补丁版本发布。

## 修复范围

- `TerminalView` 触摸拖动调用 `doScroll(..., true)`，强制滚动 scrollback。
- 触摸 fling 不再沿用 mouse tracking 的程序内滚动范围，改用 scrollback 范围。
- `doScroll` 增加 `forceScrollback` 参数；触摸路径绕过 mouse tracking 和 alternate screen 的方向键转换。
- Shift+Page 明确强制滚动 scrollback，与注释语义一致。
- 新增 `test/terminal-touch-scrollback-test.sh`，并接入 `scripts/test-all.sh`。

## 前置证据

- `v0.5.0` Release run `33394175165` 已取消，`v0.5.0` GitHub Release 未创建。
- 当前稳定版元数据：`versionName=0.5.1`、`versionCode=50003`、`releaseNotes=docs/RELEASE_NOTES_0.5.1.md`。
- `versionCode=50003` 高于 `0.5.0` 的 `50002` 和 `0.5.0-rc.1` 的 `50001`。
- 本地 `TERMUXPRO_USE_CHINA_MIRROR=1 ./scripts/test-all.sh && git diff --check` 已通过。

## 发布门禁

1. 热修复 PR 的完整 CI 与 Emulator UI 必须通过。
2. 热修复 PR 合入 `dev` 后，merge commit 收尾 CI 必须通过。
3. 创建 `dev → master` 发布 PR；发布 PR 的完整 CI 与 Emulator UI 必须通过。
4. 发布 PR 合入 `master` 后，在 `master` 合并提交创建不可覆盖标签 `v0.5.1`。
5. Release 工作流必须先完成正式签名 APK 覆盖升级验收，再创建 GitHub Stable Release。
6. Release 必须非 Draft、非 Pre-release，并包含 APK、`SHA256SUMS` 和 `APK_SIGNATURE.txt`。
7. 稳定 Release 完成后，`dev` 必须对齐 `master` 发布提交并等待收尾 CI 成功。

## 发布结论

进入 `0.5.1` 热修复稳定发布流程。若任一门禁失败，停止发布并记录失败证据；不得覆盖既有 `v0.5.0` 或
`v0.5.0-rc.1` 标签。
