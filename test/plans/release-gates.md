# 发布门禁

`dev` 合入 `master` 前必须同时满足：

- 全模块 JVM/Robolectric 测试、Lint、Debug 和 Release 构建通过。
- APK 包名、版本、Launcher、ARM64 ABI、SHA-256 及发布证书校验通过。
- Android 运行时门禁按变更风险分层：API 21 最低兼容、API 28 目标行为和当前 API 35+ 至少各有
  自动化覆盖；360dp、深色、默认/200% 字体、软键盘 resize、Activity/进程恢复和网络重连相关用例通过。
- 只有涉及物理键盘/输入法厂商实现、锁屏保活、通知、存储、网络切换、PTY 或 OEM ROM 行为的变更，
  才要求至少一台 ARM64 实体 Android 或云真机作为稳定版硬门禁。设备品牌只是兼容样本，不得把三星、
  小米或任一用户私有设备写成所有版本的固定通行证。
- 品牌兼容抽样采用风险驱动轮换：优先覆盖原生/近原生 Android 与至少一种深度定制 ROM；发现厂商专属
  缺陷时再将对应 ROM 加入该功能的定向回归集，不把单台设备通过外推为所有 Android 设备通过。
- 真实 SSH 主机完成密码/密钥、主机指纹变化、失败诊断和本地回环端口验证。
- 真实 Claude Code 与 Codex CLI 完成启动、恢复、确认、拒绝、中断和大输出搜索。
- 不存在未关闭 P0/P1 缺陷，不包含秘密、私钥、真实账号或未脱敏日志。
- README、版本说明、验收报告和签名指纹与候选 APK 一致。

没有触发真机专属风险的版本，可由上述 Android API/布局矩阵、真实 SSH fixture 和 Release 校验形成稳定
发布证据。触发真机专属风险但证据缺失时可以继续在 `dev` 或候选版验证，不得把相关能力声明为通过，
也不得发布包含该未验收高风险变更的稳定版。
