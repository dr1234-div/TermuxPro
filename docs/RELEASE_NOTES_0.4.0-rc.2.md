# TermuxPro 0.4.0-rc.2 候选版发布说明

这是 `0.4.0` 的第二个候选版本。应用功能范围继续保持 `0.4.0-rc.1` 的远程 tmux 会话中心，不并入新的
产品功能；本候选版用于验证修正后的发布流水线和签名 APK 覆盖升级门禁。

## 相对 0.4.0-rc.1 的变化

- Release 流水线改为先构建正式签名 APK，再在隔离模拟器中验证“上个稳定版 → 当前候选版”的覆盖升级，
  验收通过后才创建公开 GitHub Release。
- 稳定基线选择只允许使用低于当前候选版本的正式 Release，避免误选候选版、自身版本或更高版本。
- 研发 PR 的自动门禁不再触发由 `github-actions[bot]` 创建 PR 导致的 `pull_request action_required`
  噪声；研发分支继续依赖同 SHA 的 push CI 与模拟器 UI 门禁。
- GitHub CLI 项目封装默认绑定 `heydarey/TermuxPro`，避免在 fork/upstream 场景下查询到官方上游仓库。

## 0.4.0 功能范围

- tmux 会话中心支持新建、进入、重命名和停止，形成完整生命周期。
- 新建会话绑定当前服务器、项目目录和 TermuxPro ownership；同名冲突会明确失败，不覆盖已有会话。
- 未知归属的共享 tmux 会话保持只读，只允许进入，避免误删或污染其他用户工作。
- 重命名和停止前重新核验 owner、工作区指纹及 tmux 实例身份，归属变化时失败关闭。
- 写操作期间锁定列表并展示具体进度；网络结果不确定时要求刷新核对，避免盲目重复提交。

## 验收重点

1. GitHub Release 创建前必须先完成正式签名 APK 覆盖升级验收。
2. 从 `0.2.0` 稳定版覆盖升级后，UID、Launcher、桌面名称、进程和 AndroidRuntime 状态必须正常。
3. 默认字体与 200% 字体下，会话中心、新建、重命名和停止确认弹窗必须完整可读。
4. 共享 tmux 会话不得被 TermuxPro 静默接管或提供写操作。
5. Claude Code 与 Codex CLI 历史恢复仍由用户显式选择，不自动进入共享或未知上下文。

## 已知限制

- TermuxPro 只能管理带有匹配 ownership 元数据的自有会话，不会接管既有共享 tmux 会话。
- Claude Code 与 Codex CLI 历史会话仍使用各自原生选择器，统一 AI 会话元数据中心尚未完成。
- Android 实体设备或云真机上的软键盘、弱网、后台恢复及 OEM 行为仍需按风险矩阵补充证据。

## 安装提醒

- 包名保留为 `com.termux`，与其他签名来源的 Termux 不能直接覆盖安装。
- 卸载应用会删除其私有 Linux 环境和本地配置，升级体验前请备份重要数据。
- 本版本是 Pre-release；需要稳定环境时继续使用 `0.2.0`。
