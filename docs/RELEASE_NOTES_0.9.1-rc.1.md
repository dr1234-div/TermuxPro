# TermuxPro 0.9.1-rc.1 候选版发布说明

`0.9.1-rc.1` 是 `0.9.0` 之后的体验补丁候选版，冻结范围只包含已合入 `dev` 并通过门禁的增值服务改动：
远程 AI CLI 启动上下文、tmux 会话归属提示、Git 工作台目标识别，以及自动化失败噪声治理。

## 核心变化

- tmux 会话中心细分归属状态：当前工作区、其他工作区、其他 TermuxPro 使用者、归属标记不完整和未标记
  会话分开提示；非当前工作区会话只允许显式进入，不提供重命名或停止，降低共享服务器误操作风险。
- Claude Code/Codex CLI 启动前展示当前远端目标；配置不完整时明确提示，避免在共享账号或多项目场景下
  误进入错误服务器、错误目录或错误历史会话。
- Git 工作台首屏展示 `host:port · path`，用户在查看分支、修改、提交、同步前能确认当前操作属于哪台
  远端机器和哪个项目。
- 自动 PR/Actions 治理补充单一控制器和失败噪声复核：保留真实 Release 失败证据，区分并发取消、替代
  成功 run 和真实 CI/模拟器失败，减少无效失败提醒对维护判断的干扰。
- 产品范围继续收敛在 TermuxPro 增值服务；Termux 原始终端、PTY、包管理、本地 shell、基础会话和
  基础快捷键能力只做不受影响回归守护。

## 验收重点

1. 远程 tmux 会话列表必须明确展示会话归属，不允许对非当前工作区会话执行写操作。
2. Claude/Codex 快捷启动必须先展示当前远端目标；历史入口仍只打开 CLI 原生选择器，TermuxPro 不自动
   进入最近历史。
3. Git 工作台必须在首屏展示远端主机、SSH 端口和项目路径；既有分支、修改、提交、同步操作不回退。
4. GitHub Actions 若出现失败提醒，维护者必须能区分真实失败、并发取消和已被替代的成功 run。
5. 360dp 深色主题、默认字体和 200% 字体下，tmux、AI CLI 和 Git 相关入口仍可读、可操作。

## 已知限制

- 本候选版仍不解析 Claude Code/Codex 的私有历史元数据，也不展示跨用户历史内容；历史选择继续交给 CLI
  原生选择器。
- 远程 tmux 的归属判断依赖 TermuxPro 写入的 owner 元数据和运行时校验；归属未知或标记不完整时安全降级。
- 本地共享服务器不启动 Android 模拟器；运行时截图和覆盖升级验收由 GitHub Actions 隔离模拟器执行。

## 安装提醒

- 包名仍为 `com.termux`，与其他签名来源的 Termux 不能直接覆盖安装。
- 升级前请备份重要本地 Linux 环境和配置；卸载应用会删除应用私有数据。
- 如果已安装 `0.9.0` 正式版，可直接覆盖升级到本候选版本。
