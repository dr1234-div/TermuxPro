# TermuxPro 虚拟产品团队工作流

项目负责人对最终结果负责，但不得用一个人的开发自检冒充团队闭环。每个纵向切片必须经过独立的产品、
设计、开发和质量角色；角色可以由按阶段启动的智能体承担，不要求智能体空闲时常驻，但每个门禁都必须
留下当前版本证据和明确结论。

## 团队角色与真实产出

| 角色 | 必须交付 | 独立决定权 |
|---|---|---|
| 产品负责人 | 主动发现池、用户旅程、优先级、范围/非目标、验收标准 | 可删除低价值需求；可因不解决用户问题驳回 |
| UI/UX 负责人 | 当前版本体验审计、流程/信息架构、状态与异常方案、改前/改后证据 | 可因复杂、误导、不一致、不可读或不适合移动端驳回 |
| 架构/开发 | 风险方案、实现、自动化测试、迁移/回滚、维护成本说明 | 可因安全或架构不可控退回重新设计，不得自行降低产品标准 |
| QA 负责人 | 独立测试设计、执行记录、缺陷、回归面和证据缺口 | 可因未测、不可复现、证据不足或回归失败驳回 |
| 发布负责人 | 签名、构建、升级、Release、回滚和产物校验 | 可阻止不满足发布门禁的候选版本进入 `master` |
| 项目总负责人 | 组织角色、解决冲突、维护节奏和最终交付 | 不能覆盖产品/UI/QA 的失败结论强行宣称通过 |

以上只是每轮最低闭环，不是固定团队上限。项目负责人维护动态能力池，并按当前纵向切片的风险启动专项
智能体；不能等用户点名角色，也不能让所有角色长期空转制造形式主义。

## 动态能力池与启动条件

| 专项能力 | 必须启动的条件 |
|---|---|
| 用户研究/产品分析 | 新主线、反馈冲突、需求价值不明、同一问题反复返工 |
| 交互/UI 设计 | 新页面/流程、信息架构变化、用户认为难用、任何可见 UI 缺陷 |
| 无障碍/输入法 | 表单、终端输入、对话框、字体/主题、TalkBack 或软键盘相关变更 |
| Android/终端架构 | Activity/Service/PTY/bootstrap、生命周期、存储或上游 Termux 差异变化 |
| SSH/tmux/AI CLI 专项 | 连接、认证、指纹、远端命令、会话发现/恢复或共享账号行为变化 |
| 安全与隐私 | 密钥、凭据、日志、通知、命令拼接、远端文件、会话隔离或权限变化 |
| Android 开发 | 进入设计就绪且架构边界清楚的实现阶段 |
| QA 自动化 | 每个代码切片；在开发前参与用例设计，开发后独立执行与驳回 |
| 真机/厂商兼容 | 输入法、后台、网络、通知、ROM、性能或 RC 候选版 |
| 性能与资源 | 启动、滚动、终端输出、长任务、隧道、内存/电量或包体变化 |
| CI/发布工程 | 工作流、依赖供应链、签名、候选版、升级、回滚或稳定发布 |
| 技术文档/上游同步 | 用户行为变化、配置/迁移变化、上游合并或对外交付 |

项目负责人每轮在任务卡记录“已启动角色、未启动角色及理由”。新风险出现时立即补充专项能力并返回对应
门禁；既有角色或流程不再适合时可以调整本文，而不是把初版团队结构固化。

## 每轮状态流

1. **发现**：产品从真实体验、用户反馈、Issue、CI/崩溃、测试缺口和平台变化主动建立候选问题。
2. **产品定义**：写清用户问题、旅程、证据、优先级、非目标、成功指标和产品驳回条件。
3. **设计就绪**：UI/UX 用当前版本证据完成流程、页面状态、文案和大字体/软键盘方案；未通过不得开发。
4. **开发就绪**：架构确认安全不变量、上游差异、迁移、回滚和测试策略，开发完成纵向切片。
5. **QA 验证**：QA 独立执行正常、异常、回归和适用设备用例，不接受开发者口头自测替代证据。
6. **产品与设计双验收**：重新完成原始旅程并比较改前/改后指标；任一角色驳回就返回相应阶段。
7. **合入与观察**：CI 全绿后合入 `dev`；设备能力经过候选版观察，发布门禁通过后才进入稳定版。
8. **复盘与再发现**：检查是否真正减少步骤/风险，挑战一个既有假设，再产生下一轮候选问题。

## 任务卡最小字段

- 用户与使用场景
- 当前问题及本轮证据
- 影响旅程与 P0/P1/P2
- 期望结果、非目标和设计目标
- 正常/异常/中断路径
- 安全、隐私、性能和上游兼容风险
- 产品、设计、QA 各自验收标准与驳回条件
- 自动化、模拟器、真机证据及明确未覆盖项
- 发布、迁移和回滚方式

## 当前产品主线

优先级按完整用户旅程而非现有模块数量排列：

1. 可信地连上服务器。
2. 十秒内回到上次工作，但不自动进入未知或共享会话。
3. 在手机上完成一次 Claude Code/Codex 编码循环，覆盖长提示、软键盘、中断和恢复。
4. 判断 AI 修改了什么，并在两步内回到终端。
5. 安全运行并预览项目。

低频工具不应与核心连接和会话任务竞争首页；核心主线未达到证据门禁前，不以增加入口制造进展感。

当前“状态驱动首页 + 可信连接”切片需要产品、UI/UX、Android/终端架构、SSH/会话安全、无障碍/输入法、
Android 开发和 QA；性能角色在实现阶段检查首页与终端，无障碍/真机兼容在候选 APK 上执行，发布角色在
RC 门禁启动。后续切片重新评估，不自动沿用本轮名单。

## 驳回原则

- CI 绿色但核心任务仍难找、难懂、难恢复，产品或设计必须驳回。
- 模拟器截图不能替代软键盘、触控、网络、后台、真实 SSH/tmux/AI CLI 和厂商 ROM 证据。
- 只完成正常路径，或错误页暴露退出码却没有恢复动作，QA 必须驳回。
- 200% 字体裁切、中文未测、危险操作常驻、状态虚假或共享会话可能误入，直接按阻断问题处理。
- 任何角色的“通过”必须绑定版本和证据；旧版本结论不能自动继承到当前版本。
