# TermuxPro 0.8.1 正式版发布说明

`0.8.1` 是 `0.8.0` 之后的体验补丁正式版，来自已发布并通过门禁的 `0.8.1-rc.1` 候选范围。
本版本不再加入新的未验证功能，重点修复真实使用反馈中的终端滚动、会话管理、AI CLI 启动安全提示和
GitHub 自动化失败邮件噪声。

## 主要变化

- 终端触摸滚动增加明确模式：默认保护 shell 输入，手机上下滑动优先查看历史输出；在 Claude/Codex、
  vim、less 等需要内部滚动的 TUI/AI 场景，可从终端工具箱切换为“AI/TUI 面板”模式。
- 本地终端会话侧栏支持关闭当前会话，并在会话行级菜单中支持切换、重命名和关闭；关闭操作只影响本地
  Termux 会话，不触碰远程 tmux。
- 终端会话切换、关闭和异常退出反馈不再出现空白 Toast 或 `null - exited`。
- Claude Code/Codex CLI 启动弹窗补充上下文：默认新建会话，历史入口只打开 CLI 原生命令选择器；
  共享 Claude 账号不再被 TermuxPro 静默续接最近历史。
- 自动研发 PR 降低失败提醒噪声：预合并 CI/UI 失败时保留 PR 并成功退出，不和核心 CI 重复发送失败邮件。
- 自动 PR GitHub CLI 调用增加命令级超时、重试和 Actions 查询容错，避免 GitHub API 抖动或 CLI 卡住
  造成长时间 pending 或不可解释失败提醒。
- 推送前冒烟门禁会按变更类型补跑相关测试，减少 UI、中文文案、终端、Git 和 tmux 入口问题被远端 CI
  首次发现。

## 验收重点

1. 手机终端长输出可以用手指查看历史；进入 Claude/Codex/vim/less 等场景时，可从工具箱切换滚动模式。
2. 终端侧栏能找到本地会话关闭入口；关闭确认文案说明不会停止远程 tmux。
3. 终端所有 Toast 都必须有可读文字，不出现纯白空提示。
4. Claude/Codex 快捷启动不会静默续接最近历史；共享 Claude 账号默认新建会话。
5. GitHub Actions 新增失败时，维护者能区分真实 CI 失败、自动 PR 等待状态和外部 App 空检查噪声。

## 已知限制

- 终端滚动手感已通过模拟器和策略测试覆盖，但真实手机输入法、厂商 ROM 和高刷滚动手感仍需要持续采样。
- 远程 tmux 会话管理仍遵循归属隔离；归属未知或其他用户会话只允许显式进入，不提供越权重命名/停止。
- GitHub 外部 App 的 queued 空 check suite 不是本仓库 Actions 失败；若未来被设为必需检查，需单独治理。
