# TermuxPro 0.9.4-rc.1 候选版发布说明

`0.9.4-rc.1` 是 `0.9.3` 之后的候选体验版，冻结范围只包含 TermuxPro 增值服务和自治发布流程改进。
本版本不重做 Termux 原始终端、PTY、包管理、本地 shell、基础会话、基础快捷键或基础文件能力；这些
能力仅作为“不被增值层破坏”的回归面。

## 主要变化

- 快捷指令页新增模板入口：Codex、Claude、Git、tmux 和前端检查模板可直接预填编辑器，降低手机软键盘
  手写命令成本。模板不会自动保存或执行，仍经过危险命令确认和秘密检测。
- AI CLI 启动弹窗补强上下文：工作台入口继续展示远程目标；终端工具箱入口明确提示命令会发送到当前
  可见终端会话，避免在错误 SSH、tmux 或项目目录中误启动 Claude Code/Codex CLI。
- AI CLI 新建/历史操作项展示实际将执行的命令，例如 `claude`、`claude --resume`、`codex` 和
  `codex resume`。
- 自动研发 PR 改用 GitHub Pulls API 创建，避免 `gh pr create` 在 Actions 中进入交互式等待，减少
  pending/fail 通知噪声。
- 项目规则进一步明确：Termux 已有基础能力只做兼容守护，TermuxPro 主线只打磨远程工作区、AI CLI、
  tmux/Git 可视化、自定义快捷指令、移动端工作流和工具箱增值服务。

## 验收重点

1. 快捷指令模板只预填编辑器，不自动落盘或执行。
2. 无效工作区下模板和新建入口不可用。
3. 终端工具箱启动 AI CLI 时必须提示当前可见终端风险。
4. 历史 AI 会话入口仍只打开 CLI 原生选择器，TermuxPro 不自动进入最近会话。
5. 360dp、默认字体和 200% 字体下关键页面保持可读和可操作。
6. 原始 Termux 终端、PTY、本地 shell 和基础会话语义不得被修改。

## 已知限制

- 本候选版不读取 Claude/Codex 私有历史文件，也不展示 CLI 内部历史列表；历史选择仍交给 CLI 原生选择器。
- 本地共享服务器 KVM 不可用，模拟器 UI 验收依赖 GitHub Runner。
