### 已完成纵向切片：Git 工作台基础闭环（0.3.0）

- 用户与场景：开发者进入远程项目后，需要先确认当前仓库、分支和工作树状态，再查看分支、切换分支、
  审查修改和最近提交，不应为了常用只读信息反复输入 Git 命令。
- 当前证据：0.2.0 只有“Git 修改审查”，成功态把分支、状态和 Diff 混成一段终端文本；没有当前分支、
  修改计数、分支列表、分支切换或提交记录入口，错误态也无法区分非 Git 仓库与 SSH/路径故障。
- 优先级：P1（高频开发工作流缺少状态感知和导航闭环）。
- 期望结果：首屏展示仓库路径、当前分支或 detached HEAD、未提交修改数量与上游同步状态；提供“分支、
  修改、提交”三个清晰入口。分支列表区分本地/远端，切换必须显示目标并在脏工作树时二次确认；所有操作
  完成后刷新真实状态，不伪造成功。
- 非目标：本轮不实现提交、推送、强制切换、重置、变基或删除分支；这些高风险写操作须另立切片。
- 已启动角色：产品、UI/UX、Git 领域架构、Android 开发、安全和 QA。
- 产品驳回条件：用户仍需从原始 Git 输出猜当前分支/修改数量，或无法从同一页面到达分支与提交记录。
- 设计驳回条件：状态层级不清、分支切换缺少当前/目标对照、空仓库与错误态混淆，或 360dp/200% 字体裁切。
- 安全驳回条件：分支名未经 Shell 转义、允许任意文本执行、脏工作树静默切换，或把失败展示成成功。
- QA 驳回条件：普通分支、detached HEAD、无上游、干净/脏工作树、非 Git 仓库与切换冲突缺少测试证据。
- 完成证据：PR #37 已合入 `dev`。产品页可直接确认仓库路径、当前分支、修改数量和上游同步状态，
  可查看本地/远端分支、显式切换本地分支、审查修改与最近提交；真实临时 Git 仓库测试、全量 CI、
  模拟器默认字体和 200% 字体截图均通过。高风险写操作仍按原约束进入后续独立切片。

### 当前纵向切片：自定义快捷指令（0.3.0）

- 用户与场景：开发者在不同服务器和项目中反复运行构建、测试、日志、Git 或 AI 辅助命令；内置工具无法
  覆盖个人工作流时，应能把可靠命令保存为工作区工具，而不是每次在软键盘上重新输入。
- 产品目标：在终端内按需工具箱中提供用户指令管理，支持创建、查看、编辑、复制、排序、启停和删除；
  每条指令可配置名称、命令、工作目录、分组和执行前确认级别，并按工作区隔离保存。
- 首个交付闭环：完成“空状态 → 新建 → 校验 → 保存 → 列表 → 预览实际命令 → 确认执行 → 编辑/删除”
  全路径；取消编辑、非法输入、工作区切换、应用重启和命令执行失败均不得丢失或串用数据。
- 安全边界：不支持在模板中保存密码、Token 或私钥；命令必须展示最终展开结果和目标工作区，高风险命令
  默认二次确认；用户输入不能拼接进未转义的内部控制命令，日志与诊断包必须脱敏。
- 产品驳回条件：只能新增不能维护，离开首页才能使用，预置与用户指令无法区分，或用户看不到命令将在哪个
  服务器、目录执行。
- UI/UX 驳回条件：入口仍堆在首页、空状态没有明确动作、编辑页在 360dp/软键盘/200% 字体下不可完成，
  删除与执行使用相同视觉层级，或列表只能靠难辨认图标操作。
- QA 驳回条件：CRUD、排序/启停、持久化、工作区隔离、变量校验、危险确认、执行失败恢复和升级迁移任一
  缺少自动化或运行时证据。
- 非目标：首轮不做云同步、跨设备共享、公共指令市场，也不允许指令绕过 SSH 主机身份与工作区可信状态。

## P1

### 0.2.0 真机反馈：开发者工作流与可发现性

- 产品发现机制升级：产品负责人每轮不只消费用户已提出的功能点，必须以至少一条真实开发者旅程主动
  记录目标、频率、阻力、替代动作、误操作风险和退出路径；交付问题清单、取舍理由和验收结论。不得把
  “页面有入口”视为需求完成，也不得用控件数量代替开发效率。
- Git 工作台纵向切片：展示当前仓库/当前分支、可切换分支、本地与远端分支、未提交文件数量与状态、
  提交历史和刷新状态；提供安全的分支切换/新建、差异查看、暂存/取消暂存、提交等高频操作。冲突、脏
  工作树、detached HEAD、远端失败和危险丢弃必须明确解释并可恢复；不提供违背 Git 不可变历史语义的
  “删除提交”伪 CRUD。
- 自定义快捷指令：允许按工作区创建、查看、编辑、排序、复制、启停和删除指令，支持变量/确认级别/
  工作目录/图标或分组；执行前展示实际命令与目标，危险命令二次确认，秘密不进入模板、日志或同步。
  预置指令与用户指令分层，用户始终可以退出、撤销编辑或恢复默认。
- 终端入口可发现性：重新设计终端侧栏触发器和“移动开发工作台”入口，使用含义明确的图标、文字标签、
  首次引导与稳定位置；在 360dp、200% 字体、单手操作和软键盘打开时验证。验收包括首次使用者无需猜测
  “头像”即可在限定步骤内找到会话列表与工具箱。
- 设置视觉语义：移除无危险含义的红色顶部区域。颜色必须遵循信息/成功/警告/危险语义，危险色只用于
  破坏性动作或明确故障；同时校验深浅主题对比度和系统状态栏一致性。
- “管理工作区”概念与入口重构：明确它管理的是服务器连接、项目目录和连接后策略；根据研究结果选择
  改名为更直接的“连接配置/服务器与项目”、补充上下文说明，或合并进工作区切换器。无法在当前页面
  解释价值的入口应删除或渐进展示。
- 历史会话完整生命周期：侧栏支持新建、查看、重命名（领域允许时）、切换、停止/删除和失败恢复，删除
  前明确对象、归属与影响。会话切换反馈必须显示具体结果，不能只有空白 Toast；共享 Claude 账号不得
  暴露或误删其他用户会话。
- 多远程连接配置：允许新增和保存多个服务器/项目工作区，支持查看、编辑、复制、删除、排序/最近使用与
  快速切换；切换前保护未保存修改，身份、主机指纹、目录、tmux 策略和快捷指令按工作区隔离。0.2.0
  单配置迁移不得丢失现有数据。
- 控件与选项规模匹配：只有一个有效选项时不使用下拉选择器，直接展示固定值或隐藏控件；有多个真实
  场景时再使用选择器并解释差异。优先审计“远程开发”工作区类型，避免用选择器制造不存在的选择成本。
- tmux 会话管理纵向切片：支持安全的新建、查看、重命名、显式进入、停止/删除和刷新；区分 TermuxPro
  自有、归属未知和其他用户会话，不自动进入、不越权管理。所有操作绑定稳定 session id 与 owner 元数据，
  单会话退出只能 `kill-session`，任何产品路径不得触发默认 `kill-server`。
- 对象生命周期设计规则：对工作区、快捷指令、应用自有会话等可变对象，设计时必须逐项检查创建、读取、
  修改、删除/归档、取消、错误恢复和跨页面一致性；对 Git 提交、远端共享会话等受领域约束对象，使用
  安全的查看、筛选、恢复或受限管理替代机械 CRUD，并在界面解释限制。

- 体验/品牌：桌面应用名已固定为 `TermuxPro` 并有 Manifest 回归测试；后续发布继续纳入桌面名称与图标检查。
- 按完整旅程重排 Roadmap：可信连接 → 十秒恢复 → 手机 AI 编码循环 → 判断 AI 修改 → 运行与预览；研发治理事项与用户阻断项分栏维护。
- 分阶段拆分巨型 `WorkspaceActivity`：先抽取模型/Repository/校验与迁移测试，再建独立编辑页、状态 reducer、可信状态和一次性终端启动薄桥；不触碰 Termux Service/PTY/bootstrap 不变量。
- 建立无障碍与输入法门禁：常驻 label/`labelFor`、TalkBack 状态播报、48dp 命中区、`adjustResize`、IME Next/Done、首错聚焦、中文 composing 和草稿/旋转/进程恢复。
- 重构首页信息架构：PR #25 已完成未配置、已配置、已验证的渐进展示和单一主操作；继续补“最近 tmux/AI 会话”和可直接继续的任务上下文。
- 将 Git、远程文件、项目任务、后台任务、SSH 密钥和 Web 预览迁入终端开发场景的按需工具箱；首页不平铺低频控件，用户无需返回首页才能调用工具。
- 精简工作区管理：新增、保存、复制、删除不再作为四个同等级常驻大按钮；危险删除降级到对象菜单并明确目标。
- 合并首页重复的连接诊断/环境入口，统一加载、空、错误、成功状态与可操作修复建议。
- 建立简体中文、360dp、深色主题、默认与 200% 字体的截图矩阵；英文布局通过不能替代中文长文案验收。
- 统一未连接/组件缺失错误页：Git、远程目录、文件预览、tmux、项目任务和连接诊断已不暴露内部退出码并提供恢复动作；远端缺少 tmux 可直接打开普通 SSH。继续覆盖 SSH 组件安装动作，诊断细节按需展开。
