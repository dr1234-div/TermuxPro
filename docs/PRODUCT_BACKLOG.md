# TermuxPro 产品迭代 Backlog

本文件记录当前可验证事实，不把首版发布视为产品完成。每轮迭代关闭最高优先级纵向切片后继续审计。
产品边界：Termux 原本已经具备的终端基础能力只做兼容守护，不作为主要研究和重造方向；TermuxPro 的
主要价值应落在远程工作区、AI CLI、tmux/Git 可视化管理、自定义快捷指令、移动端交互和工具箱等增值
服务上。任何增值改动必须确保原始终端能力不受影响，失败时回退到原始终端仍可用。
用户反馈明确要求：原本 Termux 已有的功能不再进入研发研究队列，TermuxPro 只打磨增值服务，同时把
原始能力纳入兼容回归，防止增值层污染基础终端体验。
选题门禁：新增研发切片必须先证明属于 TermuxPro 增值服务；若只是 Termux 原有基础能力，只能进入
兼容回归清单，不能作为主线需求继续研究或重做。评审时必须写明分类：远程工作区、AI CLI、tmux/Git
可视化、自定义快捷指令、移动端工作流效率、上下文工具箱，或原始能力兼容守护；只有前六类进入主线
迭代，最后一类只用于证明 TermuxPro 没有破坏官方 Termux 原有能力。
产品负责人在拆需求时必须先回答“这是不是 TermuxPro 增值层”。如果只是原始终端、PTY、包管理、本地
shell、基础会话、基础快捷键或基础文件能力，不进入产品主线，只补不破坏回归、上游同步风险和安全回退。
真正进入主线的工作应围绕手机 SSH 远程开发、Claude/Codex CLI、tmux/Git 管理、自定义快捷指令和低频
工具箱，把用户从记命令、找入口、判断风险和恢复上下文的负担中解放出来。

### 已完成纵向切片：Git 工作台基础闭环（0.3.0）

- 用户与场景：开发者进入远程项目后，需要先确认当前仓库、分支和工作树状态，再查看分支、切换分支、
  审查修改和最近提交，不应为了常用只读信息反复输入 Git 命令。
- 当前证据：0.2.0 只有“Git 修改审查”，成功态把分支、状态和 Diff 混成一段终端文本；没有当前分支、
  修改计数、分支列表、分支切换或提交记录入口，错误态也无法区分非 Git 仓库与 SSH/路径故障。
- 优先级：P1（高频开发工作流缺少状态感知和导航闭环）。
- 期望结果：首屏展示仓库路径、当前分支或 detached HEAD、未提交修改数量与上游同步状态；提供“分支、
  修改、提交”三个清晰入口。分支列表区分本地/远端，切换必须显示目标并在脏工作树时二次确认；所有操作
  完成后刷新真实状态，不伪造成功。
- 非目标：本轮不实现提交、推送、强制切换、重置、变基或删除分支；这些高风险写操作须另立切片。
- 已启动角色：产品、UI/UX、Git 领域架构、Android 开发、安全和 QA。
- 产品驳回条件：用户仍需从原始 Git 输出猜当前分支/修改数量，或无法从同一页面到达分支与提交记录。
- 设计驳回条件：状态层级不清、分支切换缺少当前/目标对照、空仓库与错误态混淆，或 360dp/200% 字体裁切。
- 安全驳回条件：分支名未经 Shell 转义、允许任意文本执行、脏工作树静默切换，或把失败展示成成功。
- QA 驳回条件：普通分支、detached HEAD、无上游、干净/脏工作树、非 Git 仓库与切换冲突缺少测试证据。
- 完成证据：PR #37 已合入 `dev`。产品页可直接确认仓库路径、当前分支、修改数量和上游同步状态，
  可查看本地/远端分支、显式切换本地分支、审查修改与最近提交；真实临时 Git 仓库测试、全量 CI、
  模拟器默认字体和 200% 字体截图均通过。高风险写操作仍按原约束进入后续独立切片。

### 已完成纵向切片：自定义快捷指令（0.3.0）

- 用户与场景：开发者在不同服务器和项目中反复运行构建、测试、日志、Git 或 AI 辅助命令；内置工具无法
  覆盖个人工作流时，应能把可靠命令保存为工作区工具，而不是每次在软键盘上重新输入。
- 产品目标：在终端内按需工具箱中提供用户指令管理，支持创建、查看、编辑、复制、排序、启停和删除；
  每条指令可配置名称、命令、工作目录、分组和执行前确认级别，并按工作区隔离保存。
- 首个交付闭环：完成“空状态 → 新建 → 校验 → 保存 → 列表 → 预览实际命令 → 确认执行 → 编辑/删除”
  全路径；取消编辑、非法输入、工作区切换、应用重启和命令执行失败均不得丢失或串用数据。
- 安全边界：不支持在模板中保存密码、Token 或私钥；命令必须展示最终展开结果和目标工作区，高风险命令
  默认二次确认；用户输入不能拼接进未转义的内部控制命令，日志与诊断包必须脱敏。
- 产品驳回条件：只能新增不能维护，离开首页才能使用，预置与用户指令无法区分，或用户看不到命令将在哪个
  服务器、目录执行。
- UI/UX 驳回条件：入口仍堆在首页、空状态没有明确动作、编辑页在 360dp/软键盘/200% 字体下不可完成，
  删除与执行使用相同视觉层级，或列表只能靠难辨认图标操作。
- QA 驳回条件：CRUD、排序/启停、持久化、工作区隔离、变量校验、危险确认、执行失败恢复和升级迁移任一
  缺少自动化或运行时证据。
- 非目标：首轮不做云同步、跨设备共享、公共指令市场，也不允许指令绕过 SSH 主机身份与工作区可信状态。
- 当前证据：已完成工作区隔离存储及新增、查看、编辑、复制、排序、启停、删除；终端工具箱可进入独立
  页面，列表直接展示命令、目标服务器和目录，执行使用全新 SSH 会话。每次确认与仅危险命令确认具有
  不同行为，常见秘密拒绝落盘，失效工作区选择失败关闭而不回退其他服务器。聚焦 JVM/Robolectric、
  中文生产主题、205dp/200% 字体布局和 Lint 已通过；GitHub Actions 全模块测试与模拟器默认/200% 字体
  截图通过。产品验收确认入口未回流首页、目标明确且 CRUD 闭环；UI 验收曾因深色弹窗按钮不可读和
  超大字体标题断行为三行两次驳回，修复后的字段标签、操作层级、单行标题与滚动编辑能力通过复核。

### 当前纵向切片：远程会话中心生命周期（0.4.0）

- 用户与场景：开发者通过 SSH 进入远程项目后，需要在十秒内找到自己的 tmux 工作上下文，并在手机上
  安全完成新建、查看、重命名、进入、停止与失败恢复；不能因为共享 Unix/Claude 账号误改他人会话。

  SSH 退路。AI 默认新建，历史恢复继续进入 Codex/Claude 原生选择器，不解析或暴露共享历史内容。
- 安全边界：每次重命名、进入和停止前重新核验 owner、工作区指纹、tmux server PID、session ID 与创建
  时间；同名冲突失败关闭，名称使用严格便携字符集，任何路径禁止默认 `tmux kill-server`。
- 产品驳回条件：用户仍需返回首页或手输命令才能新建/重命名/停止，未知归属可写，或创建后展示伪成功。
- UI/UX 驳回条件：空态没有下一步，进入与停止同视觉层级，深色弹窗文字不可读，或 360dp/200% 字体下
  新建、取消、错误恢复不可达。
- QA 驳回条件：缺少名称边界、同名冲突、归属变化、外部删除、真实回环 SSH/tmux 生命周期及无
  `kill-server` 证据；只通过静态布局不得宣称运行时完成。
- 当前进度：已实现会话中心内显式新建、重命名、进入和停止，复用既有精确进入/停止和归属链。本轮继续
  增强共享 tmux 环境的判断信息：枚举会话不再按冒号切分名称，行内展示创建/活跃时间，并将归属拆分为
  当前工作区、其他工作区、其他 TermuxPro 使用者、归属标记不完整和未标记会话；非当前工作区会话只
  允许显式进入，禁用重命名和停止，避免误改其他项目或共享账号中的他人上下文；当前继续补强列表安全
  排序和页面解释，当前工作区会话优先展示，同类内按最近活跃排序，顶部明确提示“其他归属只读管理”，
  减少共享账号下误点未知/他人会话或误解按钮缺失的概率；待完成真实回环 sshd/tmux、全量 CI、
  360dp 默认/200% 字体截图与运行时复验。
