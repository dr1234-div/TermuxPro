# TermuxPro 0.9.2-rc.1 候选版发布说明

`0.9.2-rc.1` 是 `0.9.1` 之后的候选体验版，冻结范围只包含 TermuxPro 增值服务改进。
本版本不重做 Termux 原始终端、PTY、包管理、本地 shell、基础会话或基础快捷键能力；这些能力仅作为
“不能被增值层破坏”的回归面。

## 主要变化

- 终端内新增 AI 工具箱启动入口：用户在远程终端上下文中可直接启动 Claude Code 或 Codex CLI，减少返回
  首页和重新选择目标的步骤。
- AI CLI 启动前统一展示当前远程目标，明确主机、端口、目录和启动方式，降低共享账号、多人 tmux 或多项目
  场景下误进入错误上下文的风险。
- tmux 会话中心优先展示当前工作区相关会话，并补充安全提示：非当前工作区或归属不明会话默认只允许显式
  进入，不提供重命名、停止等写操作。
- Git 工作台支持按文件查看改动，并对单个文件执行暂存或取消暂存；便于手机端处理小范围变更，不需要手动
  输入完整 Git 命令。
- 项目规则强化“只打磨增值服务”的准入边界：远程工作区、AI CLI、tmux/Git 可视化、自定义快捷指令、
  移动端工作流效率和上下文工具箱可进入主线研发；Termux 原有基础能力只做兼容回归。

## 验收重点

1. 终端工具箱入口必须在不影响原始终端输入、滚动和快捷键的前提下启动 Claude Code/Codex CLI。
2. AI CLI 启动前必须展示清晰的远端目标，配置不完整时必须阻止误启动并给出可读提示。
3. tmux 会话列表必须优先突出当前工作区会话，对非当前工作区会话保持只读/显式进入边界。
4. Git 文件级操作必须只影响选中文件的 index 状态，不自动提交、不推送、不丢弃工作区内容。
5. 原始 Termux 能力不得因 TermuxPro 增值入口被污染、截获或削弱。

## 已知限制

- 本版本仍不解析 Claude Code/Codex 的私有历史元数据；历史恢复继续交给 CLI 原生交互。
- Git 文件级操作聚焦暂存区管理，不包含提交、推送、分支切换、远端同步等更大闭环能力；这些已进入后续
  增值服务 backlog。
- tmux 归属判断依赖 TermuxPro 写入的 owner 元数据。归属未知或标记不完整时会安全降级，不通过取消校验
  掩盖风险。
- 真实输入法、厂商 ROM、弱网和长时间后台恢复仍需持续采样；本候选版主要依赖自动化、GitHub 隔离模拟器
  和可复核的远端命令门禁。

## 安装提醒

- 包名仍为 `com.termux`，与其他签名来源的 Termux 不能直接覆盖安装。
- 升级前请备份重要本地 Linux 环境和配置；卸载应用会删除应用私有数据。
- 如果已安装 `0.9.1` 正式版，可直接覆盖升级到本候选版本；如发现 P0/P1 问题，应回退到 `0.9.1`。
