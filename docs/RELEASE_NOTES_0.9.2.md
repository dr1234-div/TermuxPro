# TermuxPro 0.9.2 正式版发布说明

`0.9.2` 是 `0.9.1` 之后的稳定版，沿用已发布并通过门禁的 `0.9.2-rc.1` 候选范围。
本版本不加入新的未验证功能，重点发布手机 SSH 远程开发中的 AI CLI、tmux 和 Git 增值体验。

## 主要变化

- 终端内新增 AI 工具箱启动入口：在远程终端上下文中可直接启动 Claude Code 或 Codex CLI，减少返回首页
  和重新选择目标的步骤。
- AI CLI 启动前统一展示当前远程目标：主机、端口、目录和启动方式都会明确展示，降低共享账号、多项目和
  多 tmux 场景下进入错误上下文的风险。
- tmux 会话中心优先展示当前工作区相关会话，并明确提示会话操作边界；非当前工作区或归属不明会话默认
  只允许显式进入，不提供重命名、停止等写操作。
- Git 工作台支持按文件查看改动，并对单个文件执行暂存或取消暂存；手机端处理小范围变更时无需手动输入
  完整 Git 命令。
- 项目规则继续收敛在 TermuxPro 增值服务：远程工作区、AI CLI、tmux/Git 可视化、自定义快捷指令、
  移动端工作流效率和上下文工具箱进入主线；Termux 原有基础能力只做兼容回归。

## 验收重点

1. 终端工具箱入口不得影响原始终端输入、滚动和快捷键。
2. Claude Code/Codex CLI 启动前必须展示清晰远端目标，配置不完整时阻止误启动。
3. tmux 会话列表必须优先突出当前工作区，对非当前工作区会话保持只读/显式进入边界。
4. Git 文件级操作必须只影响选中文件的暂存区状态，不自动提交、不推送、不丢弃工作区内容。
5. 稳定 Release 必须完成签名 APK 构建、覆盖升级、运行时冒烟和 GitHub Release 创建。

## 已知限制

- 本版本仍不解析 Claude Code/Codex 的私有历史元数据；历史恢复继续交给 CLI 原生交互。
- Git 文件级操作聚焦暂存区管理，不包含更复杂的冲突恢复、stash 编排和跨分支工作流；这些继续进入后续
  增值服务迭代。
- tmux 归属判断依赖 TermuxPro 写入的 owner 元数据。归属未知或标记不完整时会安全降级，不通过取消校验
  掩盖风险。
- 真实输入法、厂商 ROM、弱网和长时间后台恢复仍需持续采样；当前稳定门禁以 GitHub Actions 隔离模拟器、
  Release 覆盖升级验收和自动化回归为主。

## 安装提醒

- 包名仍为 `com.termux`，与其他签名来源的 Termux 不能直接覆盖安装。
- 升级前请备份重要本地 Linux 环境和配置；卸载应用会删除应用私有数据。
- 如果已安装 `0.9.1` 正式版或 `0.9.2-rc.1` 候选版，可直接覆盖升级到本正式版本。
